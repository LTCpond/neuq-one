# 架构

## 会话与本地数据

- GoRouter 检查 `SchoolSession`，未登录时跳转登录页，恢复会话或登录成功后进入课表。旧根路径 `/` 重定向到 `/timetable`。课表、学业、服务和我的各自保留导航栈，退出或切换身份时重新创建。
- `SchoolSession` 管理离线身份，`NeuqClient` 依据真实登录、续登和教务请求更新当前账号的会话状态。连接错误保留离线身份。账号匹配与客户端代数检查会拦截退出前排队或发出的旧请求结果。
- `SchoolAuthRepository` 通过 `NeuqClient` 使用学校统一身份认证。凭据只提交到已核实的学校 HTTPS 认证表单。校方要求额外验证时停止当前登录，并可在系统浏览器访问官方教务。确认教务页的退出入口和学号后，使用原有派生标识隔离本地数据。
- FlutterSecureStorage 保存用于离线恢复的派生标识。Android 在用户选择记住密码后加密保存已验证的学校凭据，供重新启动或教务会话过期时续登。教务 HTTP Cookie 保存在内存。退出时清除本地登录记录和会话。
- 校园卡页面和后台余额读取使用同一套校园卡网页认证流程。网页跳转统一认证时，尝试用当前账号的 CAS 会话获取校园卡专用票据，由校园卡网页完成回跳。校方要求额外验证时，用户可在校园卡页完成。校验网页学号后按账号保存余额和读取时间，失败时保留旧结果。
- Drift schema 2 为旧成绩补充记分方式并添加教务快照表；schema 3 为本地考试补充结束时间，升级时按一小时为旧记录回填。登录后 SQLite 文件按账号标识隔离；旧版单设备数据库文件保留，不自动并入当前账号。
- 应用通过 Repository 读写数据。学期、课程、成绩和考试安排保存在本机，按账号隔离。同步失败时保留已有快照。数据库保留旧版考试记录。

## 教务数据

- `SchoolDataSource` 在 Android 和 iOS 上通过已验证的 `NeuqClient` 会话读取学校固定 HTTPS 路径。会话过期时优先用仍有效的统一认证会话恢复。若需密码且本机已保存，尝试一次续登。同步失败保留上一份快照。
- 课表和成绩快照经校验后原子写入，按类型保存最后成功同步时间。尚未同步、确认空数据和刷新失败分别表示。并发刷新共用一次在途请求。教务学期及记录使用稳定的 `school:` 标识，成绩行的 ID 对应单次考核，补考和重修可并存。
- 点击课表或学业栏时自动请求教务刷新，同时展示最近成功结果。学期 GPA 优先采用教务值，缺少时按对应入学年级的东秦办法以学分加权计算。累计 GPA 采用教务快照。
- 应用恢复前台时按后台时长和教务会话状态检查连接。恢复成功后刷新活跃的教务同步。课表按北京时间在午夜和应用恢复前台时更新日期，默认跟随当前教学周。

## 校园网络访问

- 经登记的只读服务由 `CampusAccessClient` 根据资源策略、用户偏好和实际请求结果选择直连或 WebVPN。自动选路按资源和当前网络缓存成功路径 5 分钟。Android 使用系统默认网络的句柄识别网络切换，其他平台比较可观察到的网络接口。直连和 WebVPN 都检查实际请求及重定向的 HTTPS 主机和路径。
- Riverpod 持有账号级 `WebVpnSessionManager`。同一账号的在途认证合并，多业务通过租约共享独立会话。后台暂停、退出账号及切换身份通过会话代数和取消信号使旧操作失效。默认空闲 5 分钟释放，回到前台校验截止时间。
- WebVPN、教务和校园卡各自管理会话。`NeuqWebVpnProtocol` 复用统一认证的表单解析和加密，使用独立的 HTTP 客户端及内存 Cookie。它需要核实过的门户入口、回调和账号校验规则，确认密码表单后才可读取已授权的凭据。用户删除密码时取消在途认证。当前生产配置提供官方浏览器入口及说明，原生协议保持关闭。[CampusAccess 接入与验证范围](campus-access.md)

## 本地通知

- 设置、前台恢复、身份或课表变化触发协调。以账号和课程周次派生稳定 ID，比较平台待处理请求及内容指纹，按 ID 更新或删除。迁移时仅识别旧 ID 范围内带课程提醒标题的记录。单条失败会保留其他有效提醒，后续重试补齐。
- Android 优先采用精确定时，撤销精确闹钟权限时按用户选择降级或暂停。以 28 个北京时间日为排程窗口，最多为课程提醒安排 380 条，并计入其他待处理通知。Android 插件提供持久化请求列表，精确闹钟在每次进程启动时按同一 ID 重新确认。iOS 使用原生通知，以 14 个北京时间日为窗口，总队列预留至少 8 个位置，课程提醒最多 56 条。
- 设置页展示实际核对的条数和覆盖日期。应用启动或回到前台时补排。即时测试使用同一图标和渠道及独立 ID，系统接收请求后仍由用户在通知中心确认显示。

## 公共数据与静态资源

- `PublicDataClient` 通过 Riverpod 提供。数据层在请求时指定数据源。空教室请求使用 `neuq-one-data`，校园地图、学校政策和 App 版本请求使用 `neuq-one-assets`。公共 HTTP 客户端不需要学校会话，统一处理超时、响应大小、条件请求和重定向限制。[接口和构建配置](public-data.md)
- 空教室使用北京时间七日快照。完整快照和 HTTP 验证信息保存在设备级 Drift 缓存中。页面可见并处于前台时每五分钟检查，选中楼栋时段到期时也会尝试。并发请求合并，失败时按 1、2、4、8 分钟退避并保留快照。楼栋更新时间取所选日期该楼栋全部已采集时段的最新采集时间。蓝色由六个有效时段的交集得出，红色依据下个有效时段的结果。过期与不可用时段分别提示。[学校考场楼层示例](https://www.neuq.edu.cn/__local/0/AC/7C/27F1AF02BE447A8B94252250A28_D7F15FCF_2F938.pdf)
- 地图和政策缓存保留原文件。静态站切换后仍可离线显示旧版已验证的地图，首次联网从新源读取完整 PNG 并保存该站点的 HTTP 验证信息。政策目录缓存继续可用，PDF 按目录的 SHA-256 校验。
- 自动更新在身份恢复后异步检查，每次启动最多触发一次。成功后间隔 24 小时，连续失败按 1、2、4、8 小时退避。手动检查可随时进行，与启动检查共享在途请求。持久化状态包含检查时间、失败次数、当前构建渠道和最近有效更新。账号退出和公共缓存清理不涉及这些偏好。
- 个人中心从同一协调器读取可用更新。主动弹窗只在应用处于前台、已登录且当前导航适合展示时开启。弹窗展示后，同版本的「稍后更新」、「前往下载」、返回键和遮罩关闭均视为已提醒。持久化无法写入时保留个人中心提示。用户可继续手动查看 Release 摘要，在系统浏览器打开 GitHub Release 页面。[部署与正式发布](deployment.md)

## 缓存和诊断

- 地图、政策和文件选择器按缓存文件字节计量。空教室和就业活动统计已存储数据的字节，SQLite 空闲页由数据库复用。清理使旧下载失去写入资格，并等待已经开始的磁盘写入。空教室一并清除内存快照、失败退避及 HTTP 验证信息。
- 诊断日志是本次运行内存中最多 150 条结构化记录。记录 UTC 时间、级别、模块、阶段、固定分类和异常类型。用户可主动复制或清除。日志输入不接收异常消息、请求地址、响应、账号或凭据。

## 日历和界面

- 周视图在左上角选择教学周，在右上角切换学期。节次轴显示每节的开始和结束时间。教务数据按每周独立合并同一教学安排的连续节次，课程块与节次轴使用同一行高。
- 课表页的教务学期来自同步或本地缓存。旧版手动课表可以继续查看、编辑已有课程和导出，编辑保存时选择学校发布的 12 个固定节次。
- 差异化空、加载和失败状态由页面处理。查询失败或离线时，课表和成绩继续显示该账号上次成功同步的快照。
