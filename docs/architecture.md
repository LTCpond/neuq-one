# 架构

## 会话与本地数据

- GoRouter 检查 `SchoolSession`，未登录时跳转登录页，恢复会话或登录成功后进入课表。旧根路径 `/` 重定向到 `/timetable`。课表、成绩、服务和我的各自保留导航栈，退出或切换身份时重新创建。
- `SchoolAuthRepository` 通过应用内 WebView 使用学校的官方教务登录流程。导航仅允许已核实的教务与统一认证 HTTPS 地址。确认教务网页同时有登录退出入口及本人学号后，App 使用派生标识隔离本地数据。
- FlutterSecureStorage 存放派生标识用于离线恢复本地访问。学校网页会话由 WebView 管理，两者生命周期独立。退出 App 账号时清除本地标识及 WebView Cookie。
- 校园卡在独立网页中使用官方认证。校园服务列表进入可见状态时通过同一官方网页更新余额。校验网页所示学号与当前账号一致后，FlutterSecureStorage 按账号保存金额和读取时间。会话过期或更新失败时保留上次成功结果。
- Drift schema 2 为旧成绩补充记分方式并添加教务快照表。登录后 SQLite 文件按账号标识隔离；旧版单设备数据库文件保留，不自动并入当前账号。
- 应用通过 Repository 读写数据。学期、课程和成绩保存在本机，按账号隔离。同步失败时保留已有快照。数据库保留旧版考试记录。

## 教务数据

- `SchoolDataSource` 在 Android 和 iOS 上安装教务网页适配器。`NeuqWebClient` 在应用自有 WebView 的 Cookie 存储中发起只读请求，每批先核验教务首页的账号，使用固定的学校 HTTPS 路径。教务会话过期时页面可发起同账号重连，重连开始前已在途的读取结果会被丢弃。
- 课表和成绩快照经校验后原子写入，按类型保存最后成功同步时间。尚未同步、确认空数据和刷新失败分别表示。并发刷新共用一次在途请求。教务学期及记录使用稳定的 `school:` 标识，成绩行的 ID 对应单次考核，补考和重修可并存。
- 点击课表或成绩栏时自动请求教务刷新，同时展示最近成功结果。学期 GPA 优先采用教务值，缺少时按对应入学年级的东秦办法以学分加权计算。累计 GPA 采用教务快照。
- 已认证的导航层在应用恢复前台时同步课程提醒并刷新教务课表，停留在其他标签时也会触发。课表按北京时间在午夜和应用恢复前台时更新日期，默认跟随当前教学周。
- 空教室使用 NEUQ One Data 的北京时间七日快照，由独立公共 HTTP 客户端读取。完整快照和 HTTP 验证信息保存在设备级 Drift 缓存中，刷新失败时按日期匹配缓存。工学馆按房间编号识别楼层，特殊编号在「其他」显示。蓝色由六个有效时段的交集得出，红色依据下个有效时段的结果。过期与不可用时段分别提示。[公共 API 契约](https://github.com/LTCpond/neuq-one-data/blob/main/docs/api.md) · [学校考场楼层示例](https://www.neuq.edu.cn/__local/0/AC/7C/27F1AF02BE447A8B94252250A28_D7F15FCF_2F938.pdf)

## 日历和界面

- 周视图在左上角选择教学周，在右上角切换学期。节次轴显示每节的开始和结束时间。教务数据按每周独立合并同一教学安排的连续节次，课程块与节次轴使用同一行高。
- 课表页的教务学期来自同步或本地缓存。旧版手动课表可以继续查看、编辑已有课程和导出，编辑保存时选择学校发布的 12 个固定节次。
- 差异化空、加载和失败状态由页面处理。查询失败或离线时，课表和成绩继续显示该账号上次成功同步的快照。
